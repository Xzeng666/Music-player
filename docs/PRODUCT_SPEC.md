# Resonance Music 标准化实施指令

版本：1.0
目标平台：Windows 10+、Ubuntu 22.04+、iOS 15+、Android 8+

## 1. 产品目标

将原 Qt 本地播放器重构为内容优先、响应式、可扩展的跨平台音乐客户端。客户端必须支持本地音乐、授权在线来源、播放/缓存、行为记录、歌曲多标签、偏好学习和可解释推荐。

## 2. 功能要求

### 2.1 播放器

- 支持本地文件和 HTTPS 音频 URL；
- 支持播放/暂停、进度跳转、上一首/下一首、音量、顺序/随机/单曲循环；
- 显示标题、艺术家、封面、时长、缓冲/错误状态；
- 保留队列和最近播放记录；
- 移动端控件触摸区域至少 44×44，桌面端支持键盘访问。

### 2.2 搜索和来源

- 来源必须实现统一 `MusicSource` 接口，业务层不得依赖网页 DOM；
- 默认在线来源使用无需密钥、可公开播放的 iTunes Preview 搜索结果；
- 本地来源允许用户导入其有权使用的音频；
- 歌曲宝只提供用户主动触发的浏览器搜索跳转，不抓取、绕过防护或解析下载地址；
- 完整曲目下载仅对明确提供下载授权的来源启用；预览音频只允许临时缓存。

### 2.3 音乐库

- 收藏、最近播放和导入歌曲持久化；
- 支持按标题、艺术家和标签过滤；
- 明确显示空状态、失败状态和恢复操作。

### 2.4 标签体系

每首歌曲可包含多个标准化标签：

- 流派：pop、rock、electronic、classical、jazz、hip-hop、folk、soundtrack 等；
- 情绪：uplifting、calm、melancholic、romantic、intense、focus；
- 能量：low、medium、high；
- 年代：按发行年份映射 decade；
- 语言：zh、en、ja、ko、instrumental、unknown；
- 场景：commute、workout、focus、relax、sleep；
- 来源：local、itunes-preview 或后续授权来源。

来源元数据优先，规则推断其次；推断标签必须记录较低置信度，允许用户修正。

### 2.5 行为和偏好

记录事件：曝光、搜索点击、开始播放、播放完成、早退、收藏、取消收藏、加入本地库、明确不喜欢。事件仅默认保存在设备本地。

偏好分值按行为权重、标签置信度和时间衰减累加；负反馈必须能降低分值。达到至少 8 个有效行为且累计置信度不低于 6.0 后启用个性化排序，之前使用热门度、新鲜度和多样性冷启动策略。

### 2.6 推荐

- 候选歌曲与用户标签向量做加权匹配；
- 加入新鲜度、来源质量、重复惩罚和艺术家多样性；
- 排除明确不喜欢的歌曲；
- 每条推荐显示主要原因，例如“因为你常听流行 · 高能量”；
- 用户可查看并重置设备上的偏好数据。

## 3. 质量要求

- 分层边界：presentation → application → domain ← data/infrastructure；
- 领域和推荐逻辑不依赖 Flutter UI，可独立单元测试；
- 所有网络请求有超时、错误映射和可重试状态；
- 不提交密钥、构建产物、用户媒体或机器配置；
- 支持深色/浅色主题、系统字体缩放、键盘焦点、读屏语义和 reduced motion；
- 在 375、768、1024、1440 宽度验证，无水平溢出；
- `flutter analyze`、单元/Widget 测试和至少一个桌面 release 构建通过。

## 4. 验收标准

1. 新用户可搜索在线预览并开始播放；失败时得到可理解的错误与重试入口。
2. 用户可导入本地音频、播放、收藏并在重启后恢复音乐库和偏好数据。
3. 播放、跳过、完成和收藏会改变标签偏好；未达阈值时明确显示冷启动进度。
4. 达阈值后推荐列表按用户偏好变化，并展示推荐理由。
5. 手机使用底部导航，宽屏使用侧栏；迷你播放器始终可达且不遮挡安全区。
6. Windows 构建通过；Ubuntu、Android、iOS 构建工作流和平台配置已提交。
7. README 包含架构、功能、来源/版权边界、环境、运行、测试、构建、平台限制和验收证据。
