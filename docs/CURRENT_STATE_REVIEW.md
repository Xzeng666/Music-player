# 现有 Qt 版本评审

评审日期：2026-08-13

## 功能盘点

旧版是一个 Qt 6 Widgets / qmake 单窗口本地播放器，已实现：

- 导入单个 MP3 文件并用绝对路径保存到 `songs.txt`；
- 播放、暂停、上一首、下一首和进度跳转；
- 顺序、随机、单曲循环三种模式；
- 侧滑歌曲列表和自定义背景图。

以下目标能力尚未实现：在线搜索/播放、下载管理、收藏、历史、歌词、歌曲元数据、标签、用户行为、偏好模型、推荐、响应式 UI、无障碍、自动化测试、CI 和发布流程。

## 主要问题

| 级别 | 问题 | 影响 |
| --- | --- | --- |
| P0 | `MusicPlayer.pro` 引用构建目录内生成的 qrc | 干净环境不可复现构建 |
| P0 | 文本和注释存在编码损坏，部分字符串边界异常 | 可维护性和编译可靠性低 |
| P0 | UI 固定为 1080×720 | 无法适配手机、平板、小屏和高 DPI |
| P1 | 启动直接选择索引 1 并切换播放状态 | 空列表时行为不确定，播放状态易反转 |
| P1 | 双击、上一首和下一首多次调用状态切换 | UI 图标和真实播放状态可能相反 |
| P1 | 随机列表耗尽后递归调用下一首 | 单曲/边界条件下可能无限递归 |
| P1 | 列表动画用局部事件循环同步等待 | 阻塞主线程，造成卡顿和重入风险 |
| P1 | 本地库使用工作目录下明文绝对路径 | 文件迁移、权限和多端同步困难 |
| P1 | 未连接音量控件，且按钮尺寸设为 0×0 | 音量功能不可用 |
| P2 | 文件名被当作唯一歌曲名，重复逻辑只处理首项 | 无法正确表达同名歌曲和多艺术家版本 |
| P2 | 资源项大量重复并包含本机构建配置 | 仓库噪声和跨平台风险 |
| P2 | 无错误状态、加载态、空状态和无障碍语义 | 用户无法理解失败原因，键盘/读屏体验差 |

## 迁移结论

旧代码没有值得继续扩展的领域层或持久化层。保留产品意图和播放模式语义，使用 Flutter 重建 UI、领域模型、来源适配器、播放器服务、推荐引擎和持久化层。旧的未跟踪 MP3、背景图和构建产物不纳入新仓库，避免版权、体积和机器相关文件污染。
